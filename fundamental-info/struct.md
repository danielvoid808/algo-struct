# Структуры данных

Структуры данных — это специфические способы организации и хранения данных в компьютере, которые позволяют **эффективно** обрабатывать информацию. Выбор структуры зависит от задачи, так как каждая из них оптимизирована под конкретные операции.

## **Базовыми структурами данных принято считать**:
- **Массив (Array)**: Фиксированный набор элементов одного типа, расположенных в памяти подряд.
- **Связный список (Linked List)**: Набор узлов, где каждый элемент указывает на следующий.
- **Стек (Stack)**: Коллекция, работающая по принципу «последним пришел — первым ушел» (LIFO).
- **Очередь (Queue)**: Коллекция, работающая по принципу «первым пришел — первым ушел» (FIFO).
- **Дерево (Tree)**: Иерархическая структура из узлов (например, бинарное дерево поиска).
- **Хеш-таблица (Hash Table)**: Структура, связывающая ключи со значениями через хеш-функцию.
- **Граф (Graph)**: Сеть из узлов (вершин) и связей между ними (ребер).

Основные операции над структурами данных:
- **Чтение / Доступ (Access)**: Получение элемента по его индексу или позиции.
- **Поиск (Search)**: Нахождение позиции элемента по его значению.
- **Вставка (Insertion)**: Добавление нового элемента в структуру.
- **Удаление (Deletion)**: Исключение элемента из структуры.
- **Обход (Traversal)**: Посещение каждого элемента структуры ровно один раз (например, для вывода).
- **Сортировка (Sorting)**: Упорядочивание элементов в определенном порядке.


## **Продвинутые и специализированные структуры данных**
- **Префиксное дерево (Trie / Бор)**: Дерево для хранения строк, где каждый узел — это символ. Используется для автодополнения (Т9) и поиска по словарю за время (O(L), где (L) — длина слова.
- **Куча (Heap / Пирамида)**: Дерево, где корень всегда содержит минимальный (Min-Heap) или максимальный (Max-Heap) элемент. Применяется в очередях с приоритетом и алгоритме сортировки Heapsort.
- **Красно-черное дерево / AVL-дерево**: Самобалансирующиеся бинарные деревья поиска. Гарантируют, что высота дерева не превысит O(log n), исключая худший сценарий поиска.
- **B-деревья (B-Trees)**: Сбалансированные деревья, оптимизированные для систем хранения данных. На них строятся индексы в базах данных (например, PostgreSQL, MySQL) и файловых системах (NTFS).
- **Граф (Graph)**: Сеть из узлов (вершин) и связей (ребер). Используется для моделирования социальных сетей, дорожных карт, нейросетей и рекомендательных систем.
- **Инвертированный индекс (Inverted Index)**: Словарь, где для каждого слова хранится список мест (документов), где оно встречается. Это основа работы поисковых движков (Elasticsearch, Google).


## **Пространственные структуры данных (для геопозиции и графики)** 
- **R-дерево (R-Tree)**: Дерево для хранения пространственных объектов (точки, многоугольники). Используется в картах и навигаторах для поиска «ближайших объектов в радиусе».
- **Quadtree (Четверичное дерево) / Octree (Октодерево)**: Деревья, рекурсивно делящие 2D или 3D пространство на 4 или 8 зон. Применяются в 3D-графике, игровых движках (определение коллизий) и сжатии изображений.

## **Вероятностные структуры данных (для Big Data)**
- **Фильтр Блума (Bloom Filter)**: Компактная структура для быстрой проверки, входит ли элемент в множество. Может ошибаться в сторону «элемент, возможно, есть», но никогда не скажет «нет», если элемент присутствует. Экономит гигабайты памяти при проверке уникальности никнеймов или URL. 
- **HyperLogLog**: Алгоритм для приблизительного подсчета количества уникальных элементов в огромных массивах данных с минимальным расходом памяти (например, подсчет уникальных посетителей сайта за месяц).

**Операции в продвинутых структурах**
Специфические структуры вводят свои особые операции:
- **Балансировка (Rotation)**: Поворот узлов в AVL/Красно-черных деревьях для сохранения минимальной высоты.
- **Пробивание / Фильтрация (Sifting)**: Смещение элемента вверх или вниз в куче для восстановления ее свойств (Heapify).
- **Слияние (Union / Merge)**: Объединение двух сложных структур (например, систем непересекающихся множеств) в одну.

## **Структуры для Машинного Обучения и Нейросетей** 
- **Тензор (Tensor)**: Многомерный массив данных (матрица произвольной размерности), оптимизированный для параллельных вычислений на видеокартах (GPU/TPU). Это фундаментальный блок для всех ИИ-моделей в PyTorch и TensorFlow.

## ** Структуры для параллельных и многопоточных вычислений**

Обычные структуры данных ломаются или зависают, если несколько ядер процессора одновременно пытаются изменить их. Для обхода этой проблемы используют:
- **Lock-Free структуры (на базе CAS - Compare-And-Swap)**: Списки, очереди и стек, которые позволяют сотням потоков одновременно записывать данные без использования «тяжелых» блокировок (mutex).
- **Concurrent Hash Map**: Разделенная на независимые сегменты хеш-таблица. Потоки могут одновременно писать в разные её части, не мешая друг другу.
- **Skip List (Список с пропусками)**: Многослойный связный список, который заменяет сбалансированные деревья в многопоточных средах. Искать в нем так же быстро, как в бинарном дереве O(log n), но добавлять элементы параллельно в разы проще.

## **Структуры для спортивного программирования и сложной аналитики**
- **Дерево отрезков (Segment Tree)**: Позволяет находить сумму, минимум или максимум на любом отрезке массива (например, с 100-го по 5000-й элемент) и обновлять значения за мизерное время O(log n).
- **Дерево Фенвика (Binary Indexed Tree)**: Более компактная и быстрая альтернатива дереву отрезков для подсчета префиксных сумм.
- **Система непересекающихся множеств (Disjoint Set Union / DSU)**: Хранит группы элементов и позволяет за мгновение O(1) на практике объединять две группы или проверять, лежат ли два объекта в одной группе. Незаменима при анализе связности сетей.

## **Лаконичные структуры данных (Succinct Data Structures)** 
При работе с геномами или миллиардами веб-страниц даже обычные указатели в памяти занимают слишком много места. Эти структуры сжимают данные почти до теоретического минимума (как архиватор ZIP), но позволяют читать и искать данные прямо внутри сжатого состояния, не распаковывая их в оперативную память. 
Сюда относятся лаконичные суффиксные деревья и битовые векторы.

## **Кэш-независимые структуры (Cache-Oblivious)**
Обычно программисты подстраивают структуры под размер кэш-памяти конкретного процессора, чтобы данные читались быстрее.
Кэш-независимые структуры (например, Cache-Oblivious B-Tree) спроектированы с помощью фрактальных алгоритмов так, что они идеально используют кэш любого процессора и жесткого диска автоматически, без настройки под архитектуру железа.
