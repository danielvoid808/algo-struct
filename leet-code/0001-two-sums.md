# Задача "Two Sum" (Две суммы)

Ее суть проста: дан массив чисел и целевое число (target). Нужно найти два числа в массиве, которые в сумме дают это целевое число.

Применяется этот алгоритм и его концепты в двух ключевых направлениях: в реальной разработке (практика) и в обучении/собеседованиях (теория).

**Практическое применение в реальных задачах**

В реальном мире программисты редко пишут функцию twoSum в чистом виде, но лежащий в ее основе принцип (поиск парных элементов с использованием хэш-таблиц) используется постоянно:
  -- Финансы и бухгалтерия (Сведение баланса): Представьте, что у вас есть список транзакций и вам нужно найти две операции, которые в сумме дают ошибочно списанную сумму. Алгоритм решит эту задачу мгновенно.
  -- Логистика и управление складом: Подбор двух упаковок или грузов, которые в сумме идеально заполнят контейнер по весу или объему, не превышая лимит.
  -- Обработка данных и e-commerce: Поиск пар товаров, которые вместе подпадают под акцию (например, "купи два товара на сумму 1000 рублей").
  -- Криптография и хэширование: Поиск коллизий или парных ключей, соответствующих определенному математическому условию.


**Теоретическое значение (Собеседования и Computer Science)**

Для разработчиков эта задача — лучший маркер понимания базовых структур данных и оценки сложности алгоритмов. Она наглядно показывает разницу между «плохим» и «хорошим» кодом: 
- Иллюстрация разницы в сложности: 
  -- **Плохой подход**: Сравнивать каждое число с каждым через два вложенных цикла. Это занимает кучу времени — временная сложность составляет O(n^2).
  -- **Оптимальный подход**: Использовать хэш-таблицу (Dictionary / HashMap). Мы один раз проходим по массиву, запоминаем то, что уже видели, и мгновенно находим «дополнение» к текущему числу. Сложность падает до O(n).

**Фундамент для сложных алгоритмов**: Принцип "Two Sum" является базовым кирпичиком для решения гораздо более сложных задач: 3Sum (поиск трех чисел), 4Sum, а также задач на поиск подмножеств и динамическое программирование (например, классическая "Задача о рюкзаке").
В первую очередь "Две суммы" — это тренажер для ума, который учит программиста не бросаться решать задачу «в лоб» перебором, а использовать память (хэш-таблицы) для ускорения работы программы в тысячи раз.
  

# Возможные решения

**прямым перебором** - ставим один указатель на первый элемент среза и считаем сумму со всеми элементами. По скорости выполнения это катастрофа - O (n^2)

**Через два указателя** - так как у нас есть отсортированный массив, то можно разместиь два указателя по краям этого массива - один слева, второй справа. Далее считаем сумму под этими указателямяи. Если сумма болше искомой, то двигаем правый указатель, а если сумма под указателями меньше, то двигаем левый указатель. Решение работает только для отсортированного массива.

```
func twoSum(nums []int, target int) []int {
    leftpointer := 0
    rightpointer := len(nums)-1

    for l < r {
        pointerSum := nums[l] + nums[r]

        if pointerSum == target {
            return []int{leftpointer,rightpointer}
        } else if pointerSum > target {
            rightpointer --
        } else {
            leftpointer ++
        }             
    }
    return []int{-1,-1}
}
```

**Через ХэшМап** - Чтобы улучшить нашу сложность во время выполнения, нам нужен более эффективный способ проверить, существует ли слагаемое в срезе. Если слагаемое существует, нам нужно найти его индекс. Какой лучший способ поддерживать отображение каждого элемента среза в его индекс? Хеш-таблица. Мы сокращаем время поиска с O(n) до O(1). Хеш-таблица создана именно для этой цели, она поддерживает быстрый поиск почти за постоянное время. В случае коллизии получение значения из хеш-таблицы может деградировать до O(n). 
Простая реализация использует две итерации. На первой итерации мы добавляем значение каждого элемента и его индекс в хеш-таблицу. Затем, на второй итерации мы проверяем, существует ли в таблице слагаемое для target - nums[i]. Важно, что слагаемое не должно быть равно nums[i]. Обходим срез, содержащий n элементов, ровно дважды. Поскольку хеш-таблица сокращает время поиска до O(1), то сложность становится O(n). Временная сложность: O(n).

```
func twoSum(nums []int, target int) []int {
        m := make(map[int]int)
    for i := range nums {
        m[nums[i]] = i
    }
    for i := range nums {
        complement := target - nums[i]
        if v, ok := m[complement]; ok {
            if m[complement] != i {
                return []int{i, v}
            }
        }
    }
    return nil
}
```


**Еще один вариант через ХэшМап** - На самом деле, мы можем решить задачу за один проход. В то время как мы выполняем итерацию и вставляем элементы в таблицу, мы также оглядываемся назад, чтобы проверить, существует ли уже слагаемое текущего элемента в таблице. Если оно существует, мы нашли решение и немедленно возвращаем ответ. Временная сложность: O(n)
```
func twoSum(nums []int, target int) []int {
    m := make(map[int]int)
    for i := range nums {
        complement := target - nums[i]
        if v, ok := m[complement]; ok {
                return []int{i, v}
        }
        m[nums[i]] = i
    }
    return nil
}
```
