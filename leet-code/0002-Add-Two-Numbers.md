# Add Two Numbers (Сложение двух чисел) 

это одна из самых классических и популярных задач на платформах вроде LeetCode (обычно идет под номером 2). Она идеально подходит для отработки навыков работы со структурами данных и понимания базовой арифметики на низком уровне.

Вот подробный разбор этой задачи, от формулировки до оптимального решения.
Вам даны два непустых связных списка, представляющих два неотрицательных целых числа. Цифры хранятся в обратном порядке, и каждый их узел содержит одну цифру. Нужно сложить эти два числа и вернуть результат в виде связного списка.

Важные допущения:
- Числа не содержат ведущих нулей, кроме самого числа 0.
- Списки передаются в обратном порядке — это огромный плюс, который сильно упрощает задачу (ниже разберем, почему).

В чем главная хитрость? Первое интуитивное желание, которое возникает у многих новичков:
- Пройти по первому списку и собрать из него число (например, 342).
- Пройти по второму списку и собрать второе число (465).
- Сложить их в обычную переменную (342 + 465 = 807).
- Разобрать результат обратно в связный список.

**Почему так делать нельзя?** - В реальном мире (и в скрытых тестах на LeetCode) длина связного списка может быть очень большой (например, до 100 узлов). Число из 100 знаков не поместится ни в один стандартный тип данных вроде int64 или даже unsigned long long. Произойдет переполнение.

**Правильный подход**: Сложение «в столбик» - Так как цифры уже идут с конца (от младших разрядов к старшим), мы можем складывать их точно так же, как нас учили в школе — поразрядно, двигаясь слева направо, и удерживая в уме «перенос» (carry), если сумма двух цифр больше или равна 10.

Алгоритм пошагово
- Создаем фиктивный узел (dummy node). Он нужен как отправная точка, чтобы нам было удобно цеплять к нему новые узлы результата, не проверяя постоянно, пуст ли наш итоговый список.
- Создаем указатель current, который будет строить наш новый список, и переменную carry = 0 для хранения переноса.
- Запускаем цикл, который работает до тех пор, пока: 
  -- Не закончился первый список ИЛИ 
  -- Не закончился второй список ИЛИ
  -- Перенос carry не равен нулю (это важно для случая, когда списки кончились, но остался перенос в новый старший разряд, например: $99 + 1 = 100$).

На каждой итерации:
- Берем значение из первого узла (если он есть, иначе 0).
- Берем значение из второго узла (если он есть, иначе 0).
- Считаем сумму: sum = val1 + val2 + carry.
- Обновляем перенос: carry = sum / 10 (целочисленное деление).
- Создаем новый узел со значением sum%10 (остаток от деления) и цепляем его к current.Next.
- Сдвигаем указатели списков (если они не nil) и указатель current.
- В конце возвращаем dummy.Next (самый первый настоящий узел с результатом).

```
package main

// ListNode определяет узел односвязного списка.
type ListNode struct {
    Val  int
    Next *ListNode
}

func addTwoNumbers(l1 *ListNode, l2 *ListNode) *ListNode {
    // 1. Инициализируем фиктивную голову и рабочий указатель
    dummyHead := &ListNode{Val: 0}
    current := dummyHead
    carry := 0

    // 2. Основной цикл сложения
    for l1 != nil || l2 != nil || carry > 0 {
        sum := carry

        // Если первый список не закончился, добавляем значение и сдвигаем указатель
        if l1 != nil {
            sum += l1.Val
            l1 = l1.Next
        }

        // Если второй список не закончился, добавляем значение и сдвигаем указатель
        if l2 != nil {
            sum += l2.Val
            l2 = l2.Next
        }

        // Вычисляем новый перенос и значение для текущего разряда
        carry = sum / 10
        current.Next = &ListNode{Val: sum % 10}

        // Шагаем вперед по результирующему списку
        current = current.Next
    }

    // Возвращаем результат, пропуская фиктивную голову
    return dummyHead.Next
}
```

**Временная сложность (Time Complexity)**: O(max(N, M)), где N и M — длины двух списков. 
Мы обходим каждый список максимум один раз. Цикл выполнится ровно столько раз, сколько цифр в самом длинном числе (плюс, возможно, один дополнительный шаг для финального переноса). 

**Пространственная сложность (Space Complexity)**: O(max(N, M)). Длина нового списка, который мы создаем для ответа, пропорциональна длине максимального из двух чисел +1 узел на случай переноса. 

**Крайние случаи (Edge Cases)**, о которых нужно помнить - При тестировании или на собеседовании обязательно стоит упомянуть эти сценарии:
- Списки разной длины: например, складываем 1 и 999 (1 и 9 -> 9 -> 9). Алгоритм корректно обработает это, подставляя 0 вместо закончившегося короткого списка. Один из списков пустой (равен 0): список содержит один узел со значением 0.
- Перенос в самый последний разряд: например, 7 + 8 = 15. Списки состояли всего из одного узла, но на выходе должно получиться два узла (5 -> 1). Условие carry > 0 в цикле отвечает за то, чтобы эта единица не потерялась.

Подход, основанный на поразрядной обработке данных с сохранением состояния (в данном случае переноса carry), только на первый взгляд кажется специфичным для одной задачи. На самом деле это фундаментальный паттерн, который активно используется в реальной коммерческой разработке и системном программировании.
